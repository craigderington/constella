**Read in full:** every file in `src/` except vendored monocypher (only the EdDSA
verify path, `is_above_l`, and X25519 use were checked); all of `explorer/internal`
and `cmd` except the tests and the vendored libraries; `Makefile`, both
`Dockerfile`s, `docker-compose.yml`, CI workflow, `deploy/**` configs and scripts,

**Not done:** no build, no test run (builds write into the tree), no fuzzing, no

`tests/*.c|py` line by line, `site/index.html`, or monocypher internals beyond the
above. **One finding (F-01) was checked by simulation**
(`scratchpad/timewarp.py`); everything else is from code reading and is tagged

**Headline:** I found nothing I can show leads to theft of funds, remote code
execution, or a C-node / Go-explorer consensus split. The transaction, signature,
nonce, overflow and framing code is carefully done. The real risks are
**liveness and denial of service on a public network** (F-01 to F-05) and
**operational/deployment** gaps (F-06, F-07, F-12).

## 1. HIGH

### F-01 Timestamp rules let one share ratchet difficulty network-wide  *(Simulated)*
- Where: `src/chain.c` `accept()` (time rules) and `chain_next_bits()`; `src/node.c`
  `next_share_time()` (the BUG-031 fix); Go mirror `consensus/chain.go` identical.
- The only time rules are `time <= now + 7200` and `time >= parent.time - 600`. There
  is no median-time-past. Retarget uses just two endpoint timestamps
  (`parent.time - ancestor[32].time`).
- Honest nodes build children at `max(parent.time, wall)` (BUG-031's fix). So one
  miner who stamps a share `now + 7200` makes every honest node stamp its shares with
  that same frozen time for up to two hours. The next retarget windows see `span ~ 0`
  and return `+32 bits` each time.
- Simulation (mean-value model, 448-bit equilibrium, 4 s target): one such share
  drives bits 448 -> 832 in ~2 h (per-share work about 12x), and the network does
  not get back to ~470 bits for ~4.6 h. Span can also go negative (each child may be
  600 s behind), which also triggers `+32`.
- Impact: cheap liveness attack by any single miner; also lets a miner bias
  difficulty on its own branch. CLAUDE.md lists "live future-time probes" as not
  done; this is the analytic case for doing them.
- Fix direction (docs only): median-of-last-11 timestamp floor; clamp per-window
  timespan to [tgt/4, tgt*4]; don't let `max(parent, wall)` propagate a future stamp
  (stamp at `parent - 600` bound or reject tips > N s ahead for mining).

### F-02 No per-peer cost control: any stranger can burn the single-threaded node  *(Confirmed (code))*
- Where: `src/net.c` `readable()`/`net_process()`; `src/node.c` `on_msg()`;
  `src/mempool.c` `add()`; `src/chain.c` `submit_one()`. `grep` finds no ban, score,
  strike, or rate-limit logic anywhere except the ADDR limiter.
- Peers authenticate with a throwaway key, so "authenticated" means nothing. Costs
  an attacker can impose, all on the one event-loop thread:
  - `MSG_TX` (175 B): `mempool add()` hashes up to 1024 pooled txs (dup check) and
    then does an EdDSA verify, before any state check. About 0.5-1 ms per frame.
    `readable()` processes ~46 frames per peer per poll pass, 16 inbound peers.
  - `MSG_SHARE` with an unknown parent: `submit_one()` runs a full Fermat PoW check
    at attacker-chosen `bits` (up to 1024) before anything ties the share to the
    chain. Invalid shares get `CH_INVALID` and the peer is kept.
  - `MSG_GETCHAIN`: `serve_chain()` allocates and walks the whole chain
    (`chain_path`), then sends up to 500 shares (~1.3 MB). No limit on repeats.
  - Connection churn: the accept loop is unbounded per poll; each inbound costs
    `getrandom` + an X25519 public key, and each valid AUTH frame forces an EdDSA
    *signature* by us.
- Impact: sync stalls, late shares (orphaned blocks), and memory/queue growth up to
  4 MB/peer. No disconnect for garbage.
- Fix direction: per-peer token buckets by message class, drop/ban on invalid
  share/tx/sig, cap GETCHAIN rate, cheap checks (bits==expected, size) before PoW,
  per-IP accept rate limit, move tx sig verify behind a sender-state check.

### F-03 Ledger hash table keyed on 4 attacker-chosen bytes + free account creation  *(Confirmed (code); not reproduced)*
- Where: `src/ledger.c` `hk()` = first 4 bytes of the address, linear probing
  (`ledger_acct`, `regrow`).
- A tx `to` field is any 32 bytes; minimum amount is 1 unit (1e-8 coin); fee may be
  0; nothing charges for account creation. An attacker can create N accounts whose
  addresses share the first 4 bytes. Every lookup then scans the cluster, so
  `ledger_build()` (run on *every* tip change and at startup) becomes O(N^2).
  Rough scale: 100k colliding accounts ~ 5e9 probes per rebuild.
- Attacker needs no PoW: zero-fee txs sit in mempools and any honest miner includes
  them when a share has room (16/share). About 6k shares of capacity and ~0.001 coin
  of funds. The damage is permanent, because the accounts live in the chain.
- The Go explorer uses Go maps (randomized), so it keeps working while nodes stall.
- Fix direction: per-process random-keyed (or full-hash) index hash (non-consensus,
  safe to change); consensus-level dust minimum and/or account-creation fee.

### F-04 Every tip change does O(history) work, including side-branch tx re-verification  *(Confirmed (code))*
- Where: `src/node.c` `rebuild_state()` (runs whenever `tip_dirty`); `ledger_build()`;
  `chain_init()` replay.
- `ledger_build()` replays genesis..tip (known backlog item). **Not documented:**
  `rebuild_state()` also walks *every non-main entry in the whole tree* and calls
  `mempool_add()` on each of its txs, every time. Already-confirmed txs fail only
  after the dup check (up to 1024 blake2b) and a signature verify. Side-branch
  shares are never pruned, so the cost grows forever. Anyone can mine side
  shares with 16 sig-valid txs each (no funds needed); each such share then adds
  ~16 x ~0.6 ms to every node's every tip change.
- Startup: `chain_init()` re-verifies PoW, signatures and science claims for every
  record; the repo's own GATE3 measured **7m52s for ~33k shares** (~14 ms/share,
  linear), and the node is not listening during replay. ~1M shares ~ 4 h.
- Impact: liveness ceiling; a node falls behind once rebuild time approaches the
  ~4 s share spacing.
- Fix direction: incremental ledger (the removed snapshot idea, with the missing
  tests); cap/age the side-branch re-offer (only recent side branches, dedupe by
  txid set); trust-on-restart checkpoint for already-validated local records.

## 2. MEDIUM

### F-05 Mempool: no eviction, minimum fee, expiry, or replacement  *(Confirmed (code))*
- `src/mempool.c`: `MP_MAX 1024`; once full, `MP_FULL` for everyone. One funded
  account can fill it with 1-unit zero-fee txs and censor all other senders until
  blocks drain it. No fee floor, no lowest-fee eviction, no TTL, no RBF.
- Also: `add()` does the signature check before the `MP_FULL` check, so a full pool
  still pays for every verify. `mempool_revalidate()` silently skips on malloc failure.
- Related (F-18): a signed tx has no validity window.

### F-06 Wallet / payout-key handling  *(Confirmed (code))*
- Addresses are raw 32-byte pubkeys in hex: **no checksum or version**. A single
  mistyped hex digit in `send` (or in `CONSTELLA_ADDR`) sends coins to an
  unspendable address with no error. `send` also does no confirmation, and the
  optional `[fee]` positional (default `0.001`) is unbounded, so `send host addr 5
  100` silently pays a 100-coin fee. (`src/cli.c:106-139`)
- `node_run()` calls `wallet_load(..., create=1)` for the payout key, **even when
  `CONSTELLA_ADDR` is set**. The node never signs, yet the payout secret seed sits in
  plaintext (`wallet.key`) on the internet-facing host, same volume as the chain.
  (`src/node.c:476`, `src/wallet.c`)
- `wallet.key` is plaintext hex; there is no encryption, no passphrase, no
  mnemonic/backup scheme; file mode is set at creation but never verified on load.
- Creation uses fixed `<path>.tmp` with `O_EXCL`: a crash between create and
  `unlink` leaves a stale `.tmp` and **every later create fails** until someone
  deletes it by hand. It also needs hard-link support (`link()`), which some bind
  mounts lack. `cli_send` early-error paths don't wipe the wallet struct.
- `send` trusts the node for `next_nonce` and balance; a malicious node can only
  cause a bad nonce (tx never valid), not theft. The wallet does not authenticate the
  node it talks to.

### F-07 Hosts without thermal sensors never mine  *(Confirmed (code); not run)*
- `src/throttle.c`: `discover()` finds no sensor on typical cloud VMs ->
  `read_temp()` returns -1 -> `sampler()` sets `duty=0`, reason `TH_SENSOR` every
  window (BUG-041's fail-safe). There is no "no sensor, run anyway" / "relay-only"
  switch. The documented Lightsail plan would get a node that syncs and validates but
  never mines. Undecided cloud mode (CLAUDE.md) should be settled with this in mind;
  the mini uses `CONSTELLA_TEMP_FILE` as a workaround.

### F-08 Found shares are silently dropped if the template ring rolls  *(Confirmed (code))*
- `src/node.c`: `TMPL_RING 4`; `drain_found()` matches a mined share to a template by
  `tx_root`. Each `job_dirty` (every accepted tx, every science claim, every tip) calls
  `update_job()` and advances the ring. A share found on a template more than 4 updates
  old matches nothing and is discarded with no log line (`found++` still counts it).
  That can lose a *block*. Also, every tx arrival restarts all workers' sieve job
  (`job_new` computes ~23k primes x 4 roots), so a tx stream directly cuts hashrate.

### F-09 Orphan pool is global, never expires, and is cheap to fill  *(Confirmed (code))*
- `src/chain.c` (16384 entries / 16 MB) and `explorer/consensus/chain.go`. Orphan
  admission checks PoW and payload root but **not `bits` against anything** (parent
  unknown), so `bits=64` shares pass at trivial cost. No per-peer quota, no TTL, no
  eviction. A full pool (`nO >= MAX_ORPHANS`) silently stops recording new orphans
  until restart. `submit_one()` and the resolver scan the list linearly; Go's dedup
  recomputes `ID()` for each same-parent entry (quadratic in same-parent count).

### F-10 Peer address tables: eclipse-weak and partly dead logic  *(Confirmed (code))*
- `src/addr.c`: 32 new x 32 + 8 tried x 32 = 1,280 slots; bucket = hash(secret,
  netgroup) only (no source grouping). An attacker across ~32 /16s can own every
  `new` bucket within minutes via ADDR (3 frames/60 s x 180 per inbound peer) and
  evict honest entries by "stalest".
- `is_stale()` compares `g_max_seen - seen > g_max_seen/4`; `seen` is unix seconds
  (~1.79e9), so the threshold is ~14 years. **Staleness weighting never triggers.**
- No dial-failure tracking or backoff; dead/blackholed entries stay and get redialed,
  each holding an outbound slot for up to `CONNECT_TIMEOUT`. `addr_good` promotes into
  `tried`, evicting the stalest tried entry outright (no demotion).
- `peers.dat` is written only on clean shutdown (`node.c:572`). A crash/OOM/SIGKILL
  loses all learned tables and promotions.
- `next_rand()` restarts at counter 0 every boot -> identical selection order each run.
- `addr_is_routable`: no 100.64/10 (CGNAT), 192.0.0/24, 192.0.2/24, 198.18/15,
  198.51.100/24, 203.0.113/24, 2001:db8::/32, NAT64 (64:ff9b::/96), 6to4/Teredo, or
  IPv4-compatible `::a.b.c.d`; port 0 and well-known ports are accepted. Combined with
  gossip, a peer can make nodes dial arbitrary third-party host:ports (scan/reflection
  nuisance, bounded by 8 outbound slots).

### F-11 Blocking DNS in the event loop; dial uses only the first address  *(Confirmed (code))*
- `src/net.c` `dial()` calls `getaddrinfo()` synchronously from `net_tick()` (every
  5 s per seed, including the default fallback seed `seed.catasterism.xyz`). A slow or
  dead resolver freezes the whole node (polling, sync, job updates) for the resolver
  timeout each time. It also connects only to `res->ai_addr` (first result); with
  `AF_UNSPEC` an unreachable AAAA first means it never tries IPv4.
- `net_client_open` (wallet) similarly has no connect timeout and mis-parses IPv6
  literals. The listener is IPv4-only (`AF_INET`).

### F-12 Binary and container hardening  *(Confirmed (code))*
- `Makefile`: `-fno-stack-protector`, static non-PIE, no `-D_FORTIFY_SOURCE`,
  no `-Wl,-z,relro,-z,now`, plus `-Os` LTO. This is an internet-facing C daemon that
  parses untrusted frames. Node and explorer images are `FROM scratch` and run as root
  with no `user:`, `read_only`, `cap_drop`, `no-new-privileges`, memory/pids limits
  (compose sets only `cpus: 1.0`). `Dockerfile` runs the full `make test` inside the
  build with `CC=cc` (fine) but nothing runs ASAN/UBSAN or fuzzers in CI (the docs
  say they were run manually).

### F-13 Handshake binding gaps; no node authentication by the explorer or wallet  *(Confirmed (code))*
- `src/net.c:163-168, 172-183`: the signed transcript is `"CSTL-HS1" || eph_self ||
  eph_peer` only. It does not include the static identities, role, network
  magic/chain id, or a protocol version, and the KDF does not include the transcript
  or ephemerals. Identity misbinding (an attacker relaying with its own id) is
  possible in principle; I found no concrete exploit because ids carry no privilege
  today. No key confirmation beyond the first AEAD frame. Good: low-order X25519
  rejected, identical-identity rejected, AEAD nonces unique per direction.
- Both the wallet and the explorer accept any server identity. An explorer pointed at
  a non-local `EXPLORER_NODE` can be fed a fake (but PoW-valid) private chain by
  anyone on path; its "ledger ok" cross-check then compares against the same source.
  Fine for same-host compose; not for a remote node. Key rotation is unimplemented
  (already a listed mainnet gate).

### F-14 Explorer database write amplification and scaling  *(Confirmed (code))*
- `store.go ApplyState` runs on every dirty flush (~2 s):
  - `UPDATE txs SET status = CASE ... ` has **no WHERE guard**, rewriting every tx row
    each flush (unlike the shares update), causing dead-tuple bloat.
  - `TRUNCATE accounts, payouts, sci_payouts` and re-`COPY` all rows each flush;
    `payouts` grows by up to (#distinct miners) per block, forever.
  - `id = ANY($1)` over the whole main path per shares row; cost is shares x height
    unless Postgres hashes the array (needs `EXPLAIN` at 50k+ shares to know).
  - `Indexer.flush` also rebuilds the full Go ledger each time.
- Same O(n) shape as the node's F-04; fine at today's height, a ceiling later.

### F-15 Explorer public endpoints: cheap to hit, expensive to serve  *(Confirmed (code))*
- `query.go Share()` (non-32-byte-hex path) and `Resolve()` use
  `encode(id,'hex') LIKE $1 || '%'` and the same on `accounts.addr`: no index, full
  table scan per request. `/share/{id}` accepts any string, so `%`/`_` act as LIKE
  wildcards (parameterized, so no SQL injection; it returns arbitrary latest share).
  Every page calls `Stats()` (meta + 3 aggregate queries); text pages call it twice.
- No rate limiting or caching in app or in the (commented) Apache config; no
  statement timeout beyond request context. Errors return `err.Error()` to clients
  (DB host/driver text leak: `server.go` 503 paths).
- XSS review: html/template is used throughout; the only `template.HTML` producers
  (`glyph`, `constellation`) emit numeric/fixed strings. No `<script>` data sinks
  except the same-origin partial refresh `innerHTML`. I found no XSS.

### F-16 Supply chain and CI  *(Confirmed (code))*
- Go 1.22 (EOL) in `explorer/Dockerfile`, `alpine:3.20` (EOL Apr 2026), `postgres:16`,
  base images unpinned by digest; `golang.org/x/crypto v0.17.0` (Dec 2023). Packages
  used (blake2b, chacha20poly1305, curve25519) have no known issue I'm aware of, but
  nothing scans them: no `govulncheck`, Dependabot, or image scan in CI. GitHub
  Actions are pinned by tag, not SHA.
- `src/vendor/monocypher.c` header says `Monocypher version __git__`, single
  commit, no recorded upstream version or hash. Its verify path does enforce `S < L`
  and curve membership (good).
- Default Postgres credentials `constella/constella` are in compose, CI, and the
  explorer DSN default; bound to 127.0.0.1, but the plan shares a Lightsail host with
  other workloads, so the password must be overridden. The compose healthcheck
  hardcodes `-U constella`.

## 3. LOW / INFO

- **F-17 `rsv` header field unconstrained** (`share.c`): any 16-bit value is valid and
  in the seed, so it's extra nonce space and share-id malleability; enforce zero if
  unintended. Also the PoW seed includes `time`, so `time` is free grinding room.
- **F-18 Txs have no expiry or cancellation**: a signed tx stays valid forever; a
  "replacement" at the same nonce is just a race (DESIGN-001 documents state-invalid
  txs staying in blocks).
- **F-19 Chain id is unchanged across testnet resets** (derived only from constants
  + genesis time), so a signed tx from a prior incarnation can replay on a fresh chain
  with the same key, nonce and balance.
- **F-20 Fermat base-2 consensus primality** (documented DESIGN-005): accepted risk;
  no practical way to exploit at these sizes that I could see.
- **F-21 Science lane economics**: `SCI_G_MIN` merit 2.17 means ~11% of primes
  qualify, so claims are cheap to produce; every node pays ~6 ms per claim verifying
  (~13 ms/share at `SHARE_MAX_SCI=2`). Zero-sum over a fixed escrow release, but a
  per-node CPU tax that scales with share rate. Needs an explicit economic review
  before mainnet.
- **F-22 No TCP keepalive / idle timeout** on the node after HELLO: half-open inbound
  peers linger until a send fails (mitigated by eviction).
- **F-23 `chain_init` (committed version)**: opens `shares.v3` without locking, so two
  daemons on one volume can interleave/truncate; created with default umask (0644).
  The in-progress uncommitted edit adds `flock`, 0600, `CH_ERROR`, and fail-closed on
  alloc errors. Worth reviewing that edit separately (e.g. `ftruncate` after buffered
  reads, flock unsupported on some mounts).
- **F-24 Tx log line mislabeled** (`node.c` `tx: <from> -> <amount>`); JSON API emits
  uint64 as numbers (precision loss above 2^53 for JS consumers); Go ledger uses
  `panic()` on overflow invariants (crash instead of error; unreachable at today's
  supply).
- **F-25 Explorer `Routable()` differs from the node** (always rejects RFC1918, ignores
  `CONSTELLA_PRIVATE_NET`); explorer has no inbound ADDR rate limit (book is bounded
  to 180).
- **F-26 Env parsing is loose**: `atoi` for duty/temp; `CONSTELLA_PEERS` silently
  truncated at 1023 bytes / 16 seeds; seed ports unvalidated.
- **F-27 Hygiene**: root `.dockerignore` excludes only `constella`, `test_constella`,
  `constella-data`, `*.log`; build context still ships `.git`, `web_session.txt`
  (original brainstorm transcript, git-ignored), and any `mini.env`. `COPY`s are
  explicit so nothing lands in images today. `.gitignore` has no `*.env`, `*.key`,
  `peers.dat`, `wallet.key` patterns. The binaries `constella`, `constella-explorer`
  etc. are ignored but sit in the tree.
- **F-28 Infra identifiers committed**: AWS account id, Route 53 zone id, ACM ARN
  (`deploy/finish-cloudfront.sh`), maintainer email (`deploy/apache/README.md`).
  Not secrets; aids recon. The script drives AWS with the operator's credentials
  (Craig-only per the production boundary).
- **F-29 `wallet_load` reads the file with `fgets` into an 80-byte buffer**: trailing
  junk after 64 hex chars is ignored; an empty or partial file returns -1 (fails
  closed, good).
- **F-30 Tuning defaults**: `throttle` per-host thermal tuned to one laptop's plant;
  `CONSTELLA_DUTY` unvalidated. Not a security issue.

## 4. Checked and found sound (so you don't re-audit these)

- Tx: 152-byte fixed layout, domain-separated signing message (`CSTL-TX2` + chain
  tag + 88-byte body), `S < L` enforced, exact-length parsing, `amount==0`, nonce
  `UINT64_MAX`, fee+amount overflow, u128 settlement math for self-transfer and
  miner==sender/recipient cases. C `ledger_apply_tx` and Go `applyTx` agree on every
  edge I traced.
- PPLNS and science payout: integer only; remainder to finder; C `pplns_pay` and Go
  `splitPay` agree, including zero-total and window bounds; sci dedup/epoch reset and
  the 512-entry cap cannot be exceeded (256 x 2).
- Share/PoW: seed covers header bytes 0..116 including `tx_root`, `miner`, `prev`,
  `time`; `K_MAX` and `bits` ranges checked before any shift (BUG-011 fix holds);
  Go `Base()` matches C bit placement; orphan payload-root check (BUG-032).
- Wire: frame length caps (`MAXPAY`), `RXCAP` 8192 cannot fill on an incomplete frame,
  share message parse is exact-length, GETADDR/ADDR bounds checked before indexing,
  per-direction keys, nonce counters, low-order X25519 rejection.
- Wallet file creation is atomic and exclusive; `parse_amount` overflow math is correct.
- Explorer SQL is fully parameterized; templates auto-escape.
- Persistence: accepted shares are fsynced before relay and abort on failure.

## 5. Suggested order if you decide to act (your call)

1. F-01 (timestamp/difficulty) and F-03 (ledger index/dust) - both consensus-adjacent
   and cheapest to fix before the chain has history you can't change.
2. F-02 + F-05 (per-peer limits, mempool policy) - required before inviting strangers.
3. F-04 (per-tip cost: at least bound the side-branch re-offer; measure rebuild time at
   100k shares).
4. F-06 (no secret key on servers; address checksum; fee guard), F-07 (decide cloud
   mode), F-08 (template ring).
5. F-12/F-16 (hardening flags, non-root, image/dependency refresh, CI scans).
6. Live probes already on your list: future-time, orphan-replay; add connection-flood,
   GETCHAIN flood, and account-collision tests.
