# Local mainnet candidate qualification

These Dockerfiles are **unapproved experimental packaging**, separate from the
frozen testnet release. They build the existing C network-4 node and Explorer
`protocolv5,mainnet` profile. They do not supply a wallet, approved genesis freeze,
production Compose profile, seed network or deployment instructions.

Run the disposable smoke test from the repository root:

```sh
python3 tools/smoke-mainnet-candidate.py \
  --out release/local/mainnet-candidate-evidence
```

The evidence directory must be new. Prerequisites: native Linux Docker with
BuildKit, access to the local Unix socket, and registry access for the pinned
builder/runtime bases. The driver ignores remote Docker contexts. It copies
only tracked public build inputs and its own candidate tooling into a new
context, excluding private untracked tests and operator state.

Expected: `results.json` ends with `status: passed`, `release_approved: false`
and every cleanup result zero. The test checks:

- C static size at most 196,608 bytes, node/Explorer version identity, and the
  Explorer's mainnet package tests.
- A copied public fork fixture against the independent C ledger oracle.
- Explicit refusal of testnet bytes placed in the candidate mainnet history
  filename, preserving those bytes unchanged.
- Two validation-only C nodes (`CONSTELLA_MINE=0`), private PostgreSQL and a
  disk-backed Explorer on two internal Docker networks, with no published ports.
- Complete Explorer/C totals and full-tip agreement, a fresh complete account
  cross-check, HTTP health, and the displayed mainnet chain ID.
- Resource limits, absence of OOM/restarts, unchanged fixture history, and
  cleanup of owned containers, anonymous database volume, networks and image tags.

All keys generated by these fixtures belong only to disposable local node
identity directories. No mining, real wallets, sensor mounts, live data or
external peers are involved. Keep the output private and ignored: logs and
container metadata include disposable database credentials. Handled failures
retain evidence and attempt cleanup; after abrupt interruption, use the exact
owned names recorded in the report for manual cleanup. Never run a broad Docker
prune against unrelated projects.

The public fork fixture contains 29 accepted records at canonical height 28.
Initial peer synchronization supplies its 28-record canonical path; the extra
side-branch record is not expected in a fresh Explorer database. The smoke test
checks that canonical count explicitly and compares the resulting full tip,
account state and ledger totals with C. The separate real-history replay audit
compares every raw record and all six SQL tables from identical frozen inputs.

This smoke test establishes fixture interoperability on the native host. It
does not qualify native ARM images, final-release provenance, valuable funds,
matching-hardware capacity, backup/restore, bootstrap diversity or production
operations. The embedded source release version is still the development
testnet RC version; candidate image labels explicitly set
`org.constella.release-approved=false`. Do not publish or relabel these images
as an approved release. Final artifacts need their own approved version,
revision, manifest, digests and qualification.
